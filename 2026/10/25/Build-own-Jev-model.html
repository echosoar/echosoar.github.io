Build own Jev model

2026/10/25 | 7 min | RSS | X / Twitter

最近一段时间，Jev 这个决策模型引发了很多热议，我也翻阅了不少文章希望能搞清楚它的原理和如何构建一个自己的 jev 模型，所以本篇文章就从一段最简单的代码开始，探讨一下 jev 的原理，以及如何基于 Qwen 训练一个可以进行决策的模型。

import torch
import torch.nn.functional as F
from transformers import AutoModelForCausalLM, AutoTokenizer

# 加载 Qwen3.5-0.8B 这个开源模型
model_path = "Qwen/Qwen3.5-0.8B"
tokenizer = AutoTokenizer.from_pretrained(model_path, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    model_path, 
    torch_dtype="auto", 
    device_map="auto",
    trust_remote_code=True
).eval()

# 构造提示词
messages = [
    {"role": "system", "content": "请根据情境做出最佳决策，直接回答选项字母。"},
    {"role": "user", "content": "发现系统内存占用达到99%，此时应该：\nA. 忽略继续运行\nB. 清理缓存或重启高占用进程\nC. 卸载操作系统\nD. 拔掉电源"}
]

# 生成带 assistant 引导头的文本，并在末尾强行拼接 "答案：" 锚定下一个 Token
prompt = tokenizer.apply_chat_template(
    messages, 
    tokenize=False, 
    add_generation_prompt=True
)
prompt += "答案："

# 获取决策项对应的 Token ID
options = ["A", "B", "C", "D"]
option_ids = [tokenizer.encode(opt, add_special_tokens=False)[0] for opt in options]

# 单次前向传播提取概率
inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
with torch.no_grad():
    outputs = model(**inputs)
    # 取最后一个位置 (-1) 的 logits
    next_token_logits = outputs.logits[0, -1, :]
    
    # 截取候选选项 A, B, C, D 对应的 logit 值
    target_logits = next_token_logits[option_ids]
    
    
    # 使用 Softmax 转化为相对概率
    probs = F.softmax(target_logits, dim=-1).cpu().tolist()

# 输出结果
decision_probs = dict(zip(options, probs))
for opt, p in decision_probs.items():
    print(f"选项 {opt}: {p:.4f}")

上面只是一个很简单的例子，通过构建了一个带有问题锚点（最后的 “答案：” ）的问题提示词，将这个提示词输入给模型后，模型就会自动进行一次前向传播，把输入的分词信息经过模型的每一层计算，最终在输出层可以获取到最后一个位置的原始输出分数（Logits），从原始输出分数中提取每个候选选项对应的分值，再通过 Softmax 函数进行归一化，转化为每个选项的相对预测概率。

# 下面是执行的输出结果
选项 A: 0.1387
选项 B: 0.7969
选项 C: 0.0349
选项 D: 0.0309

上面的例子基本展示了如何构建一个最简单的 Jev 模型，但是存在一个问题，选项使用了 ABCD 这几个字母，由于 ABCD 在各种训练预料里面存在不同的训练时概率，而且在问题中也有可能出现这些字母，这会导致最终的结果决策的准确度受到影响，所以需要优化为使用 Qwen 模型词表底部的一些没有被使用的 token 或者新增一些自定义的词插入到词表里面来替代 ABCD。

所以我构建了 <|extra_0|> 这样的自定义 token 来替代 ABCD，并插入到词表中：

options = [f"<|extra_{i}|>" for i in range(4)] 
num_added = tokenizer.add_special_tokens({
    "additional_special_tokens": options
})
model.resize_token_embeddings(len(tokenizer))

如果只是这样简单地添加替换，那么最后的输出肯定是有问题的，因为这些自定义 token 的初始向量基本上是一样的，而且并没有经过训练，所以计算出来的 target_logits 基本上是相同的：

# 下面是执行的输出结果
tensor([-0.7266, -0.7266, -0.7266, -0.7266], dtype=torch.bfloat16)
选项 <|extra_0|>: 0.2500
选项 <|extra_1|>: 0.2500
选项 <|extra_2|>: 0.2500
选项 <|extra_3|>: 0.2500

因此，还需要使用一些训练数据对这些自定义 token 进行微调，使模型能够正确区分这些 token 的含义，从而在决策时能够给出合理的概率分布。
