Evaluating LLM Performance Across Multiple Methods

2026/05/24 | 8 min | RSS | X / Twitter

A while back, when I was collecting data for llm-score , I encountered a problem: how to combine scores from different benchmarks into a single score.

For example, in data.json , a model might contain the following two scores of benchmarks:

{
  "GPQA Diamond": 0.935,
  "GDPval-AA 2": 1668
}

The former is in a range of 0 ~ 1 , while the latter is in the thousands. If I directly sum all scores or take the average, the benchmark with a large score(like GDPval-AA ) will completely overwhelm the results of other benchmarks.

Another problem is that not all models participated all benchmarks. Some models only have scores of programming benchmarks, while some models only have scores of tool-use or other benchmarks, which means the original data is actually a sparse matrix.

So, in sort.js , i did not directly calculate the average score, instead used "pairwise win-loss relationships between models" to complete the sorting.

Compare models pairwise, not by average

The first step of sorting is to compare each model with all other models in pairs.

When comparing, only compare scores that both models have been benchmarked on.

if modelA's score higher than model b on a benchmark, then count ont win for modelA, and calculate the relative lead:

const midScore = (aScore + bScore) / 2;
aWinScore += (aScore - bScore) / midScore;
aWinCount += 1;

Here, the denominator is the average of the two scores, rather than directly using the original difference.

In this way, whether it is 0.9 vs 0.8 of 1800 vs 1600 , it can be converted into a releative difference, avoiding the final result being affected by the benchmark's scores with a larger range of values.

To determine the win/loss outcome between two models, the first step in the code is to compare the win count:

if (aWinCount != bWinCount) {
    sameRanksModels[otherModel.model] = aWinCount - bWinCount;
} else if (aWin != bWin) {
    sameRanksModels[otherModel.model] = aWin - bWin;
}

In other words, priority is giving to judging which model won in more benchmarks, if both models have the same win count, then compare the average relative lead of each model when they won.

For example：

ModelA won 3 in 5 benchmarks(both a and b participated)

ModelB won 2 in 5 benchmarks

Considering the modelA is stronger than modelB

If modelA and modelB both won on 3 benchmark:

ModelA with average relative lead is 2%

ModelB with average relative lead is 10%

Condidering the modelB is stronger than modelA

The advantage of this logic is that a model lossed in more benchmarks cannot be considered stronger than another model that won in more benchmarks, even if the model has a larger lead in a single benchmark.

Build graph by loss-win relationship

After obtain the win-loss relationship between each pairs, this code will convert the result into a directed graph.

if modelA is stronger than modelB, then create a edge from A to B:

A -> B

the code is：

outEdges.get(beater).add(model.model);
beatersCount.set(model.model, beatersCount.get(model.model) + 1);

  • outEdges means which models were outperformed by a model

  • beatersCount means how many models have outperformed the current model

Next is sorting:

The code uses a topological sort from weak to strong, each time, nodes that "have not win any unplaced models" are found, there are placed first

let candidates = unplaced.filter(name => remainingOutCount(name) === 0);

If a model has no edges point to other unplaced models, it means that in the remaing models, it has not win any others, so it can be placed into the result first.

如果同时存在多个候选模型，就继续比较有多少个模型战胜过它：

candidates.sort((a, b) =>
    beatersCount.get(b) - beatersCount.get(a) || a.localeCompare(b, 'zh-CN'));

被更多模型战胜的节点会被认为更弱，因此先放入结果；如果还无法区分，最后使用名称排序来保证结果是稳定的。

Furthermore, the win-loss relationship between two models is not always passed, it may occur:

A win B
B win C
C win A

也就是胜负关系成环。这个时候不存在严格的拓扑排序结果，代码会选择剩余出边最少的模型来打破循环：

const minOut = Math.min(...unplaced.map(remainingOutCount));
candidates = unplaced.filter(name => remainingOutCount(name) === minOut);

这个处理方式并不追求完美，但可以保证在数据不完整或者存在冲突时，排序流程仍然能够继续执行下去。

Generate final rank

After sort the models， sort.js will calculate the rank of each model.

First model's rank is fixed at 10 ：

const scorePi = 10;
cur.rank = scorePi;

从第二个模型开始，每个模型都只和前一个模型进行比较。如果当前模型在共同 benchmark 中比前一个模型强，就计算平均相对领先幅度，然后叠加到前一个模型的 rank 上：

cur.rank = prev.rank + (curWinScore / curWinCount) * scorePi;

如果当前模型没有在任何共同评测中赢过前一个模型，那么两者的 rank 相同：

cur.rank = prev.rank;

所以最终生成的 rank 并不是一个百分制分数，也不表示模型的绝对能力值。是一个基于排序结果的累计距离：

  • 相邻模型之间的差距越大，rank 增长越多

  • 如果两个模型无法拉开差距，它们的 rank 会保持一致

What scene is suitable for this logic

This implement does not attempt to convert all bencmarks into a unified score, but instead convert the problem into: in many benchmark results, how much better is one model than another.

这样做有几个比较明显的优点：

  1. 不要求所有模型参与相同的 benchmark

  2. 不同评分体系之间可以通过相对差异进行比较

  3. 优先使用胜场数量，避免单个评测的大分差主导排序

  4. 胜负冲突时仍然可以通过拓扑排序的兜底逻辑输出结果

Actually, it is not a perfetc solution, if both models have no common benchmark, then whre is no direct win-loss edge between them, only rely on indirect releationship between other models, but this logic current handles the sorting of the existed data well.
